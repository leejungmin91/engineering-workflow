# 보고서 적용 규칙

보고서는 독자가 결과와 판단 근거를 다시 확인할 수 있게 작성한다. 프로젝트가 정한 경로와 형식을 먼저 따른다. 그 규칙이 없으면 채팅에 보고하고, 파일을 요청받았거나 이어하기가 필요할 때는 승인된 작업 위치에 저장한다.

| 언제 | 기록 | 다음에 쓰는 곳 |
| --- | --- | --- |
| 작업 시작 | 목표, 범위, 단계와 선행 관계, 필수 검사 | 구현자가 작업 순서와 합격 조건을 확인 |
| 변경 후 | 최종 diff 위치, 작업본 ID, 검사 명령과 결과, 미검증 범위 | 검토자가 해당 작업본을 읽기 전용으로 검토 |
| 검토 후 | 검토자와 모델, 검토한 작업본, 지적, 각 지적의 반영 결과, 재검사 | 구현자가 필수 완료 기록과 사용자 보고서에 반영 |
| 완료 또는 중단 | 실제 변경, 확인한 근거, 남은 문제와 다음 행동 | 사용자와 다음 세션이 결과나 남은 일을 확인 |

복잡한 작업은 다음 형식으로 작성한다.

1. **결과와 범위**에 사용자가 확인할 수 있는 결과를 적는다.
2. **작업 흐름**에 단계와 선행 관계를 Mermaid로 표시하고, 구체적인 예 하나로 설명한다.
3. **검증 근거**에 검사 명령, 작업본, 결과를 적고 환경·권한 때문에 확인하지 못한 항목을 구분한다.
4. **교차검토**에 다른 도구인지 같은 도구의 새 세션인지, 모델, 지적과 처리 결과를 기록한다.
5. **남은 항목**에 실패·미검증과 다음 행동을 남긴다. 같은 검사를 무한히 반복할 이유로 쓰지 않는다.

[완료 기록 검사기](harness-record.md)는 최종 보고서에 들어갈 필수 검사 상태와 작업본 ID를 대조한다. 보고서의 판단이나 실제 검사 실행은 확인할 수 있는 근거와 대조한다. Slack이나 Discord는 사용자 요청이 있을 때 별도로 연결한다.
